# Migration

## v0.1.x to v0.2.0

Update the action reference:

```yaml
- uses: scarowar/insomnia-run@v0.2.0
```

For production workflows, pin to the v0.2.0 release SHA after reviewing the release.

## Inso Version

The default Inso CLI version is now `12.6.0`.

If your workflow depends on a specific Inso version, set it explicitly:

```yaml
- uses: scarowar/insomnia-run@v0.2.0
  with:
    command: collection
    working-directory: .insomnia
    inso-version: "12.6.0"
```

## Self-Hosted Runners

Insomnia Run uses `inso` from `PATH` when it is already available. If `inso` is not available, the action installs the requested `inso-version` from the official Insomnia release assets.

Runners without public internet access should provide:

- Python 3.10 or newer
- Python package index access through the runner's pip configuration, or an internal package mirror
- `inso` on `PATH` when GitHub release downloads are blocked

## Inso Configuration

Keep existing Inso configuration files, such as `.insorc`, with the Insomnia project. Insomnia Run does not require a separate action input for Inso configuration files.

## Reports

Markdown reports show parsed results by default. Raw Inso output is not included unless `include-raw-output: "true"` is set.

JUnit XML report files are generated by default. Use the `junit-file` output when you want to upload the report or publish it with a test reporting action.

```yaml
- uses: scarowar/insomnia-run@v0.2.0
  id: tests
  with:
    command: test
    working-directory: .insomnia
    identifier: "My Test Suite"

- run: echo "JUnit report: ${{ steps.tests.outputs.junit-file }}"
```

Use raw output only in trusted workflows where the output is safe to share.

## Comments Outside Pull Requests

Pull request comments still work automatically on `pull_request` workflows.

For manual, scheduled, deployment, or push workflows, set `comment-issue-number`:

```yaml
- uses: scarowar/insomnia-run@v0.2.0
  with:
    command: collection
    working-directory: .insomnia
    comment-issue-number: "123"
```

Set the appropriate permission for comment publishing:

```yaml
permissions:
  issues: write         # for issue comments
  pull-requests: write  # for pull request comments
```
